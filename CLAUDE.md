# Lektor: notes for future Claude Code sessions

Lektor turns long documents into accessible audiobooks (DAISY 2.02 full text
and full audio, M4B, MP3) for the alternative formats service at the
University of West London library. The full brief lives in the first
session's conversation; the essentials are below. Keep them.

## Hard constraints (never break these)

1. **The operator cannot install anything.** They are a librarian and a
   Python beginner on a locked laptop. Everything happens in Google Colab
   (free tier, T4 GPU) and Google Drive. Every action is a notebook cell
   driven by `#@param` form fields. Never require a terminal, a local install
   or editing Python code.
2. **You cannot run Colab or a GPU.** Design so almost everything is testable
   with the `mock` engine. The user runs `notebooks/Smoke_Test.ipynb` and
   pastes the PASS/FAIL table back.
3. **Open models only**, running inside Colab. No paid cloud speech APIs in
   the prototype. Keep `lektor/engines/base.py` clean so one can be added later.
4. **Licences**: Apache 2.0, MIT, BSD or similar only. No non-commercial or
   research-only weights by default. Record every model's licence in
   `docs/engines.md`. (Avoid AGPL libraries: we read EPUB ourselves instead of
   using `ebooklib`.)
5. **No cloning of real people's voices.** Reference clips must be synthetic
   (made by a voice design model) or carry a documented licence. Consent-based
   cloning is a later phase.
6. **Copyright hygiene**: never commit book content, extracted text, page
   images or generated audio. `.gitignore` blocks the usual file types. Test
   fixtures are generated by the tests (`tests/fixtures.py`).
7. **Fidelity to the author** (CDPA s31B): normalise for speech, drop page
   furniture, add clearly marked library notes (secondary voice). Never
   paraphrase, summarise, reorder or rewrite the author's prose.
8. **Check before you pin**: look up current docs, model cards and PyPI pages
   before choosing versions. The T4 is Turing: no FlashAttention 2; use SDPA
   or eager attention.
9. **Colab etiquette**: no keep-alive tricks. Rely on resumability.

## Architecture in one screen

- `lektor/` package; every stage reachable as `python -m lektor <stage>`.
- `script/script.md` is the single source of truth (format: `docs/script-format.md`).
- Engines and Docling run in isolated `uv` virtual environments under
  `/content/lektor_envs/` (`lektor/envs.py`); the main process never imports
  engine packages. Workers speak JSON lines over stdin/stdout.
- Book data lives in Drive: `MyDrive/Lektor/books/<book_id>/...`
  (`lektor/config.py: BookPaths`).
- Every stage is rerunnable and skips valid finished work.

## Working with the user

- Do not ask about technical choices; record assumptions in `CHANGELOG.md`.
- Ask only about things affecting the student or the library's legal
  position (for example the accessibility statement wording).
- One pull request per milestone. End each milestone with exactly which
  notebook, branch and cells to run in Colab.
- Notebooks are generated by `tools/build_notebooks.py`; edit that, not the
  `.ipynb` files.

## Tests

`pytest -q` (CPU only). Docling tests run only if Docling is installed;
network tests are skipped when models cannot be downloaded.
