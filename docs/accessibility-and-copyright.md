## The legal basis

Lektor makes accessible copies for print disabled students. There are two
bases, recorded for each book as `permission_basis` in `book.yaml`:

- **publisher permission**: the publisher has agreed in writing (for
  *Making Music*, Ableton supplied the PDF for this purpose);
- **s31B**: section 31B of the Copyright, Designs and Patents Act 1988, which
  allows an authorised body to make an accessible copy of a work for a
  disabled person who has lawful access to a copy.

Section 31B allows only the changes **necessary to make the work
accessible**. That is why Lektor is strict about what it changes.

## What Lektor may and may not change

| Lektor **does** | Lektor **never** |
|---|---|
| Read the author's words aloud exactly as written | Paraphrase, summarise or simplify |
| Expand abbreviations, symbols, numbers and music notation so they can be spoken ("4:1" is read "four to one") | Reorder sentences, paragraphs or sections |
| Drop page furniture: running headers and footers, printed page numbers, line end hyphens | Remove content because it seems unimportant (tables of contents and indexes are kept in the script, marked not to be read) |
| Read figure captions, footnotes and tables | Invent facts about figures (descriptions are typed or approved by the librarian) |
| Add **library notes**, clearly marked and read in a second voice | Present library words in the author's voice |
| Speak a front matter statement saying what the copy is and that the voice is synthetic | Hide that the narration is synthetic |

Text normalisation is applied to a separate *spoken* version of each
sentence. The *display* text in the DAISY book stays exactly as the author
wrote it.

## Statement templates

These are spoken at the start of every audiobook (in the secondary voice)
and stored in each package's metadata. `{...}` fields are filled from
`book.yaml`.

**Accessibility statement**

> This accessible copy has been made by the University of West London
> Library for the personal use of a print disabled student, under
> {permission from the publisher | section 31B of the Copyright, Designs and
> Patents Act 1988}. It must not be shared or sold.

**Acknowledgement**

> Original work: {title}, by {author}, published by {publisher} in {year}.
> All rights in the original work remain with the copyright holder.

**Synthetic voice**

> This audiobook is narrated by a synthetic voice. Words added by the
> library, such as figure captions and notes, are read in a second voice.

## Record keeping

The library must keep records of accessible copies it makes. After
packaging, Lektor appends one row to `MyDrive/Lektor/production_records.csv`:

| Column | Meaning |
|---|---|
| date | when the package was made |
| book_id, title, author, publisher | from `book.yaml` |
| source file | the file the copy was made from |
| permission basis | publisher permission or s31B |
| formats produced | for example `daisy, m4b, mp3` |
| engine and voice preset | for example `kokoro / kokoro-bf-emma` |
| Lektor version | the software version |
| recipient code | whatever reference the librarian typed |

**Never store students' names** in Lektor. The recipient code is a
reference you can look up in the library's own system.

Each book's `production_log.txt` records every stage that was run, when,
and with which settings.

## Copyright hygiene in the code

The Lektor repository never contains book content, extracted text, page
images or audio. Test documents are generated by the tests themselves from
short passages written for the purpose.
